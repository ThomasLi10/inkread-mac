# 墨读 MVP：实现与后续范围

版本：0.2.0。目标是先建立“PDF 原文 → 选段／图表 → 讨论 → 可编辑笔记 → 回到原文”的完整个人阅读流程。

外观支持浅色、深色及跟随系统，应用级 NSAppearance 统一驱动窗口、面板和 SwiftUI，设置保存在 UserDefaults。深色 PDF 阅读通过公开 PDFDocumentDelegate 自定义 PDFPage，在 PDFKit 原生页面／tile 绘制上下文内进行差值反色，将白纸显示为近黑、黑字显示为浅白；不使用整层 Core Image 滤镜，避免文档被低分辨率栅格化。切换时失效并重绘原生 tile，不重载文档，不改缩放、选区坐标、原文件或区域截图。彩色图片也会受到显示变换，用户可独立关闭。主题绿在深浅外观中分别调整对比度。

原生反色经过 200%／400% 字形像素对照验证，没有边缘位移或重采样；同时验证了旋转、非零裁切原点、透明纸张和原色区域截图。实际 321 页书籍中，同一页、同一缩放的浅色／深色与 PDF 反色开关已通过 GUI 对比，文字保持清晰且页面位置不变。

0.2 增加原生目录、当前章节、后台本书查找（前 200 处匹配）、匹配高亮、原生缩放与适应窗口、阅读历史、可收折调宽面板、专注模式及 ⌘K 命令面板。讨论历史和笔记有独立搜索，Markdown 回答支持代码与表格，页码引用可点击定位。草稿按书籍／讨论隔离保存在本应用 UserDefaults，持久化内容仍由书库管理；快速切书前会提交待保存的阅读位置。

## 当前结构

| 模块 | 职责 |
| --- | --- |
| `InkRead` | SwiftUI 可收折阅读工作台、AppModel 状态、导入与原文提取、笔记编辑、阅读位置和回复保存 |
| `PDFReaderView` | AppKit／PDFKit 阅读、文本选区、区域截图、引用高亮与回跳；不重写原 PDF |
| `InkReadCore` | Foundation Codable 模型、SHA256 去重、本地 JSON 原子保存、Markdown 导出与恢复检查 |
| `CodexBridge` | 启动本机官方 CLI 子进程，以 stdio JSONL 协议创建／恢复线程，发送文字及本地图片，处理流、停止、超时和错误 |

应用与界面是自主实现，PDF 渲染使用系统 PDFKit，图标使用系统 AppKit 绘制。未将 Skim、Zotero 或 Sioyek 的代码复制进项目。当前仓库未设置开源许可证；后续是否开源单独决定。

## 数据模型与文件

每份 PDF 有稳定的书籍 UUID。原文件内容的 SHA256 用于识别重复导入，同一份文件改名不会生成第二本书。

- `Book`：标题、页数、零基阅读位置、标签字段和导入时间。
- `SourceAnchor`：文档 UUID、零基页索引、原始页标签、PDF 页面坐标、选中文字、截图相对路径和周边文字。
- `Discussion`：所属文档、引用锚点、Codex 线程 ID、多轮消息及时间。
- `ChatMessage`：用户／助手角色、正文、生成中／完成／失败／中断状态。
- `Note`：所属文档、可选讨论关联、标题、正文、来源锚点及时间。

默认存储在 `~/Library/Application Support/InkRead/`。根目录 `manifest.json` 是元数据的唯一来源，各书籍的 `books/<UUID>/` 目录保存 `source.pdf`、`BOOK.md`、逐页文本和截图。**这里是原子 JSON 本地库，没有 SQLite，也没有向量数据库。**

变更先验证并写盘，写盘成功后才更新发布给 UI 的数据。保存失败不能显示为已保存。启动时拒绝不可解码／不受支持的数据，存在书籍内容而缺少元数据时也拒绝以空库代替。附件路径检查禁止离开书库。初始化会把旧的生成中消息恢复为中断状态，并保留已保存的部分正文。

导入保留原始 PDF 副本，阅读器的引用位置标记仅作用于内存 PDF 视图；没有把它当作完整的 PDF 批注格式。Markdown 导出暂时引用本机 PDF 与截图路径，没有打包附件，因此不应宣称已实现可迁移的独立导出包。

当前存储假设一个应用进程管理一个书库；暂未实现跨进程锁与冲突合并。增加后台索引器或独立同步进程之前，需要重新设计并发写入边界。

## Codex 与上下文

每次讨论保存对应的 Codex 线程 ID。继续同一个讨论时恢复线程，而不是把每条消息伪装成完全独立的请求。不同讨论拥有各自的线程；书籍目录是该书的工作目录。

选择文字时提供准确的选段、页码和周边文字；框选时额外发送渲染的 PNG，不能把图表理解退化为单纯 OCR 文本。导入产生逐页文字文件和目录索引，Codex 按需要读取相关页，避免默认把整本长书塞进每次请求。

接入的是本机 CLI，不表示模型运行在本机。认证由官方 CLI 管理，应用不提取认证令牌。应用请求只读、无审批的独立会话，禁用继承的 MCP 和扩展功能；进程停止、协议异常或权限返回不符时应报告错误。网页搜索仍依赖实际 Codex 配置和服务能力。

流式回复需要在生成过程中保存检查点；停止、完成和正常退出时收尾保存。即使某次元数据写入失败，当前答案也应保留在 UI 以便复制。异常关闭后的恢复只能保留此前成功写入的内容，不能保证恢复最后一个尚未写入的片段。

## 验证边界

自动化测试覆盖存储语义和模拟 Codex 协议行为。真实端到端验证还需要分别确认文本选段、多轮续聊、图表视觉输入、笔记关联、退出恢复和导出。

2026-11-04：17 项自动化测试通过。真实 AppModel／Codex 测试完成文本提问、同线程续聊记忆、仅凭 PNG 读出图表数值、保存真实回答、重新加载书库及 Markdown 导出，全程约 27 秒。图表结果准确读出 A=10、B=20、C=30 和最大值 C:30。真实 GUI 中也验证了文件面板导入去重、鼠标文本拖选、鼠标图表框选、笔记打开及从第 1 页回跳第 2 页原图表。release 打包、图标与本地签名校验通过。

测试使用隔离库和自造 PDF，不使用用户现有阅读材料。早期诊断曾因目录 URL 尾斜杠比较而误报隔离失败，已改为规范化路径比较并重新通过；诊断结果只写报告，错误不会再弹出前台测试提示。尚未用大量真实书籍验证长文性能、复杂排版和扫描件。

随后在用户明确提供测试文档后，额外使用一份 321 页、约 8.8 MB 的真实技术书完成正式 App 实测：全部页面提取与目录索引成功，框选第 41 页架构图发送给 Codex，Codex 成功只读查阅第 42 页原文并生成带页码的中文解释；续聊摘要保存为示例笔记，并实际从第 200 页回跳第 41 页图表。该测试也促成了书库重命名入口的补充。文档副本、图像和讨论留在本机书库，不纳入源码仓库。

## 下一阶段

优先根据实际阅读反馈优化当前流程，再逐项加入以下能力：

1. **PDF 批注工具**：高亮／下划线、颜色、自由笔迹、箭头与形状；先设计独立批注模型、撤销和保存策略，再增加标准 PDF 批注导出。
2. **标签与目录理解**：先读标题、摘要、目录或代表页提出粗标签；长书按章补充。区分 AI 建议和手工确认标签，保留修改依据，避免后台反复覆盖用户标签。
3. **关联与复习**：同书笔记双向链接、讨论摘要、相关概念推荐和历史结论引用；再增加跨书检索与可选择的跨书上下文。
4. **扫描件与检索**：OCR、版面和公式处理、索引任务状态、跨书全文检索；需要时再引入 SQLite／FTS 或向量检索，不能把预留字段宣称为已完成能力。
5. **可迁移数据**：包含 PDF、图片、笔记和引用的导出包、备份恢复、数据格式迁移和同步冲突设计。

这些是后续范围，当前版本没有承诺完成时间，也没有把它们放入现成功能清单。
