# 墨读 · InkRead

围绕一本 PDF 阅读、提问和积累笔记的 macOS 原生应用。当前版本为 0.5.2，是可继续开发的个人阅读 MVP。

应用主体使用 SwiftUI、AppKit 和 PDFKit 自主编写，调用本机官方 Codex CLI 的 `app-server` 协议。项目没有复制第三方阅读器的源码，也没有为项目预设开源许可证。

## 下载与安装

在 [GitHub Releases](https://github.com/ThomasLi10/inkread-mac/releases) 按版本下载应用；最新版本见 [Latest Release](https://github.com/ThomasLi10/inkread-mac/releases/latest)。

- **系统要求**：macOS 14 或更新版本。当前预编译包为 Apple Silicon（M1/M2/M3/M4 及更新的 M 系列）`arm64`，不适用于 Intel Mac。
- **推荐 DMG**：下载 `InkRead-版本号-macOS-arm64.dmg`，打开后将“墨读.app”拖入 `Applications`。也可放到 `~/Applications`，然后在 Finder 中打开。
- **ZIP 备选**：下载同版本 `.zip`，解压后把“墨读.app”移到应用程序目录。不要下载 GitHub 自动生成的 `Source code` 来安装应用。
- **首次打开**：当前包使用本地 ad-hoc 签名，尚无 Apple Developer ID 签名和公证。如果 macOS 阻止打开，在确认从本仓库下载后，按 [Apple 官方说明](https://support.apple.com/en-us/102445) 前往“系统设置 → 隐私与安全性 → 仍要打开”。组织管理的 Mac 可能不允许例外。
- **Codex 功能**：PDF 阅读、批注和本地笔记不需要 Codex；讨论、翻译、标签建议等 AI 功能，需要使用者自行安装并登录官方 Codex CLI，或配置本机可用的 Codex 可执行文件。安装包不包含账号、登录凭证、阅读内容或 AI 使用额度。
- **升级**：先退出旧版，再用新版替换原应用。书库位于 `~/Library/Application Support/InkRead`，与应用包分开；重要笔记建议先导出备份。当前没有应用内自动更新，需从 Releases 手动下载。

每个版本附 `SHA256SUMS.txt`，供核对下载文件。公开仓库只改变代码可见性，当前未授予额外开源许可证。

## 打开墨读

已安装版本位于 `~/Applications/墨读.app`。在 Finder 按 ⇧⌘G，输入该路径并回车即可打开；也可在终端运行：

```bash
open "$HOME/Applications/墨读.app"
```

打开后可在 Dock 图标上右键，选择“选项 → 在程序坞中保留”。升级后如果旧窗口仍在运行，先按 ⌘Q 退出，再重新打开以使用新版本。

## 当前可以做什么

- 导入一份或多份 PDF，为每份文档建立独立书籍目录；相同文件内容通过 SHA256 去重。
- 阅读 PDF、跳转页码、恢复上次阅读位置。
- 工具栏“外观”、菜单栏“外观”和设置页均可切换浅色、深色或跟随系统，选择自动保存。
- 深色时默认将 PDF 白底黑字显示为深底浅字；可独立关闭“深色时反转 PDF 颜色”查看原色。此显示变换会同时影响彩色图片，原 PDF、保存的图表截图和发送给 Codex 的图片均保持原色。
- 在书库中右键重命名书籍，或在 Finder 中显示 PDF 副本。
- 选择原文文字，或在一页内框选图表、公式区域，发起 Codex 讨论。
- 为讨论保存选段、页码、页面坐标、截图和周边文字；从讨论或笔记回到原文位置。
- 保存多轮讨论、停止正在生成的回答，把回答整理成可编辑笔记。
- 保存期间保留部分回复；重启时把未完成回复标为已中断。保存失败时提示错误，并保留当前未保存答案供复制。
- 在本书内查看历史讨论、搜索笔记，并导出本书的 Markdown 笔记与讨论。
- 导入时提取目录和逐页文字，供 Codex 按需查阅原文。Codex 也可在所用客户端和服务支持时进行网页搜索，回答中应给出实际来源。

阅读器会显示原文引用与自定义彩色批注。高亮、下划线、方框及文字备注独立保存在书库，支持本次运行内的撤销／重做，不改写 PDF 原文件。

## 0.5 独立阅读记录与精简讨论面板

- **阅读讨论留在墨读**：讨论、翻译、标签建议和术语释义使用 Codex 临时会话（`ephemeral`），不写入 Codex 的持久聊天列表。每轮根据墨读已保存的消息与来源快照续接理解；退出重开或停止 Codex 子进程后仍可继续阅读讨论。
- **历史图片继续可用**：追问时一并带入历史消息实际引用的图片。清空当前引用材料或选择别处，不会改写先前发送的来源，也不会让旧图表在下一问中消失。
- **常用操作靠前**：历史讨论放进可搜索弹层；原文引用与材料按需展开，提问建议、回答方式和次要操作收进菜单，主区域用于阅读问题与回答。模型和 effort 保留在输入区下方。

旧版保存的 Codex 线程 ID 仅作为兼容数据保留，新请求不再恢复它们。临时会话改变的是聊天记录存储方式；模型请求仍使用现有 Codex 登录，并向其模型服务发送本次所需的选段、图片和历史内容。

## 0.4 选词翻译与模型设置

- **选词翻译**：在 PDF 中选择英文单词或短语，点击“翻译”，结合所在页的上下文给出中文释义。翻译显示在独立浮层，不占用阅读讨论；只有点击翻译时才调用 Codex，不因每次拖选自动发请求。
- **保留词条来源**：翻译开始时记录原词、所在书籍、章节和选区。继续翻页或选择别处后，词条仍指向最初的原文；点击“加入术语手册”才保存到本书手册，并可从词条回跳。相同词条和章节合并原文来源，保留已有释义，避免覆盖手工修改。
- **模型与 effort**：讨论输入区和设置页可选择模型与推理力度，模型列表来自本机 Codex 的 `model/list`，effort 只显示所选模型支持的值。选择会保存；“默认”沿用 Codex 的默认设置。
- **请求采用同一设置**：模型与 effort 应用于新讨论、已有讨论的下一问、标签建议、术语释义和选词翻译。修改设置作用于之后发起的请求，正在生成的内容继续按发起时的设置完成。“简洁／深入／启发”仍控制回答方式，与 effort 分开。
- **阅读字号**：界面主要文字小幅调大约 1 pt，讨论与输入正文约 14–15 pt，表格与代码相应调整；PDF 保持原有缩放与矢量清晰度。

翻译使用现有 Codex 登录和服务，不另接第三方翻译平台；需要可用的 Codex 连接与额度。扫描件需要文字层才能直接选词。模型是否可用取决于当前账号、CLI 和服务返回，加载失败可刷新重试。

## 0.3 阅读工具与 Codex 交互

- **彩色批注**：选中文字点颜色即可高亮，框选图表后点颜色添加方框；选区更多菜单或 ⇧⌘H 可设置下划线、颜色和备注。在“整理 → 批注”查找、编辑、删除和撤销；标记上右键或按住 Option 点击可编辑。
- **标签修订**：书籍菜单和 ⌘K 中打开“修订本书标签”，手工增删标签，也可按需请 Codex 根据内容提出建议。建议需要点选并保存才应用；书库搜索支持标签。
- **疑问队列／续读卡**：保存待理解、待核实、已解决的问题，可关联原文和讨论；继续讨论只准备草稿，不自动发送。打开书籍有续读入口，“整理”中可查看当前章节、上次讨论、最近笔记和未解决问题。
- **术语与符号手册**：按书籍和章节记录术语／符号、释义和原文来源；支持同符号在不同章节的独立定义。可按需请 Codex 拟释义，再编辑保存。
- **上下文篮**：选区、图表、笔记、术语和旧回答可组成下一问材料，支持多张图像；每条问题保存独立的材料快照。修改篮子不会改写旧消息。一个笔记或回答可以保留多处来源。
- **固定参考页**：⇧⌘P 固定当前页或选区，阅读区较宽时左右对照，较窄时上下排布；参考页独立缩放，主阅读器继续翻页。页面、裁切和文字保留原生矢量，不使用整页图片替代。
- **Codex 体验**：明确区分进度提示与最终回答，生成过程中可写下一问，提供解释／推导／举例／检验草稿模板、简洁／深入／启发三种回答方式、运行阶段及耗时、停止、消息分支和明确的新分支重试。模板只填草稿；重试只在用户点击后执行，不自动重放问题。

新增快捷键：⇧⌘C 加入上下文篮，⇧⌘H 批注编辑，⇧⌘P 固定参考页。批注、疑问和术语都包含在 Markdown 导出中；图像与 PDF 仍由本机链接引用。

## 0.2 阅读工作台

- 可收折、可拖动调宽的两侧面板，专注阅读会收起两侧并恢复先前布局。
- 本书原生 PDF 目录、当前章节指示，以及后台全文查找、匹配高亮和循环跳转。单次最多显示前 200 处匹配；扫描件需要文字层。
- 原生缩放、适合宽度、整页显示、阅读位置前进／后退。PDF 渲染继续使用原生页面绘制。
- 讨论历史可搜索与收折，选区工具紧贴文字或图表浮动显示，随滚动、缩放和面板尺寸变化重新定位；当前讨论引用始终单独展示，切换选段不会偷偷改写旧讨论。
- 回答以原生 Markdown 排版，支持段落、标题、列表、代码、表格和复制。`[PDF 第 N 页]` 可点击回到原文。
- 讨论草稿各自保存，切书／重开恢复最后讨论与页码。保存旧回答为笔记会沿用其讨论来源。
- ⌘K 命令面板支持中文或英文关键词、方向键、回车和 Escape。

| 操作 | 快捷键 |
| --- | --- |
| 命令面板／导入／新讨论 | ⌘K / ⌘O / ⌘N |
| 查找原文／下一处／上一处 | ⌘F / ⌘G / ⇧⌘G |
| 目录／导航栏／讨论面板 | ⇧⌘O / ⇧⌘L / ⇧⌘B |
| 专注阅读 | ⇧⌘F |
| 实际大小／适合宽度／整页 | ⌘0 / ⌘1 / ⌘2 |
| 放大／缩小 | ⌘+ / ⌘− |
| 讨论选段／写笔记／发送 | ⇧⌘D / ⇧⌘S / ⌘Return |
| 翻译选中英文 | ⇧⌘T |

## 开发与运行

需要 macOS 14 或更新系统及已就绪的 Xcode／Swift 工具链。没有第三方 Swift 包依赖，无需安装 Node、Python 或数据库服务。

用 Xcode 打开项目根目录的 `Package.swift`，选择 `InkRead` 运行方案，然后运行。也可以在项目目录中执行：

```bash
swift run InkRead
```

命令行运行适合开发；日常使用建议打包成 `.app`。

## 构建与安装 App

在项目根目录运行：

```bash
./scripts/build-app.sh
open build/墨读.app
```

脚本完成 release 构建，使用 AppKit 绘制图标，通过系统 `iconutil` 生成 ICNS，并使用本地 ad-hoc 签名生成 `build/墨读.app`。该签名不联网，不需要开发者账号，也不包含 Apple 公证。构建产物使用当前主机的架构，尚未配置通用二进制分发。

需要安装到个人应用目录时运行：

```bash
./scripts/build-app.sh --install
```

目标为 `~/Applications/墨读.app`。若已有同名 App，脚本只替换 `CFBundleIdentifier` 为 `local.thomas.inkread` 的旧版本，并把旧版本保存到 `~/Applications/InkRead Backups/`。同名但标识不同的文件或符号链接会保留，并停止安装。安装不修改书库，不执行设置默认 PDF 阅读器的操作。

## 制作版本安装包

维护者在 macOS 上运行（需要上述 Swift 构建环境与 Python 3）：

```bash
./scripts/package-release.sh
```

脚本读取应用版本和架构，在 `release/<版本>/` 生成 `.dmg`、`.zip` 和 `SHA256SUMS.txt`，并检查包内应用、签名、ZIP CRC 和 DMG 只读挂载结果。`--skip-build` 可使用已有的 `build/墨读.app`；`--output-dir DIR` 可指定输出目录。已有同名发布文件时会停止，避免改写已经分发的版本。

将版本对应的 Git 提交打上 `v<版本>` 标签，在 GitHub Releases 新建同名版本并上传这三个文件，即可保留每一版的安装包和更新说明。打包脚本只在本地生成文件，不会自动上传或安装应用。制作包仍使用现有 ad-hoc 签名，不会自动获得 Developer ID 或 Apple 公证。

## 连接本地 Codex

1. 确保官方 Codex CLI 已安装，并已完成登录。在可找到 `codex` 的终端中可使用 `codex --version` 和 `codex login`。
2. 打开墨读的“设置”，查看“本地 Codex”。路径留空时，应用会检查常用 CLI 安装位置及官方桌面应用内置 CLI。
3. 如果自动查找失败，选择实际的 `codex` 可执行文件，再点“应用设置”。例如官方桌面应用中可能位于 `ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`。
4. 导入 PDF，选择文字或框选图表，点“讨论此处”并发送问题。

墨读复用 Codex 自己的登录状态，不读取或导出其认证令牌。“本地 Codex”指接入本机 CLI；模型推理仍取决于 Codex 所使用的模型服务，选段、截图和按需读到的原文会作为请求内容发送给该服务。

应用为自己的子进程请求只读工作环境，禁用继承的 MCP 服务和扩展能力，并在实际协议返回不满足权限设置时停止。不要把这理解为离线模型或任意本机文件的独立安全隔离边界。

## 数据在哪里

默认书库位于：

```text
~/Library/Application Support/InkRead/
├── manifest.json
└── books/
    └── <书籍 UUID>/
        ├── source.pdf
        ├── BOOK.md
        ├── pages/
        │   ├── page-0001.txt
        │   └── …
        └── assets/
            └── <选区 UUID>.png
```

`manifest.json` 是书籍、讨论、笔记、批注、疑问、术语、阅读工作区、引用锚点和内容指纹的元数据来源，采用 JSON 原子替换写入，**当前没有使用 SQLite**。每份 PDF 的内容文件放在独立 UUID 目录中。讨论消息和逐次来源快照是续聊依据；旧版 Codex 线程 ID 字段保留兼容，新讨论不再保存该 ID。

导入会复制 PDF；应用不改动你选择的原文件，也不把阅读位置标记写回 `source.pdf`。批注引用和笔记独立保存在知识库。迁移或备份时复制整个 `InkRead` 书库目录，不能只复制 `manifest.json`。若书库元数据损坏，应用会报告错误，不会用空库覆盖它。

“导出笔记”生成一份 Markdown，包含本书笔记、讨论、选段和页码引用。原文与截图链接目前指向本机书库文件；导出的 `.md` **不包含 PDF 和图片副本**，移到其他电脑前还需携带对应文件。可在设置中打开书库目录。

0.3 使用 schema 2 元数据，兼容读取 schema 1；首次保存前自动将旧元数据原始字节保存在 `manifest-v1-backup.json`。新格式不能被 0.2 旧二进制直接读取。如需回滚，应先退出 App、备份完整现有书库，再同时恢复旧 App 和对应旧元数据；直接覆盖旧元数据会丢失升级后新增内容。普通升级不需要手工处理这些文件。

## 当前限制

- 扫描 PDF 没有 OCR，无法凭空建立全文文字索引；框选图像仍可作为视觉讨论输入。
- 尚无自由手绘、箭头和带批注 PDF 导出；本版提供彩色高亮、下划线、方框与文字备注。
- 标签建议为按需调用、人工确认；尚无后台自动修订、全库标签合并和规则系统。
- 尚无跨书全文检索、跨书讨论组合和自动关联推荐。
- 尚无同步、多人协作、iPad／Apple Pencil 输入、加密 PDF 解锁界面。
- 文字跨页选择当前保留第一页的选段及坐标；需要讨论多页时请分别选择，或直接指明相关页码。
- Codex 的可用模型、登录有效性、网络搜索和额度由实际客户端及服务决定。应用不会自动重放失败请求，以免向同一线程重复提交问题。
- 同一个书库面向单个应用进程使用，尚未实现多进程协作编辑与文件锁。

多图输入依据官方 [Codex App Server](https://developers.openai.com/codex/app-server) 的 `turn/start.input` 列表协议，并用本机 CLI 生成的 schema 和真实图像请求验证。

## 验证

运行自动化测试：

```bash
swift test
```

测试覆盖本地库重启恢复、内容去重、引用与笔记导出、损坏拒绝覆盖、落盘失败、附件路径检查，以及 Codex 协议解析、停止、超时和模拟进程行为。测试与真实联网模型调用是不同层次的验证。

建议每个发布版本手工检查：

1. 导入包含文字与图表的 PDF；翻页后退出重开，确认阅读位置恢复。
2. 选中文字发起讨论；框选图表另开讨论；确认引用页码、选段与截图正确。
3. 连续追问，停止一段尚未完成的回答；退出重开，确认已保存的内容和中断状态。
4. 把回答保存为笔记，编辑后重开；点击“回到原文”和“查看讨论”核对关联。
5. 导出 Markdown，核对正文、两种对话角色、图片及原文页码链接。
6. 同时拖入多个 PDF、再次导入同内容 PDF，核对批量导入和去重。
